## Problem

The header "Login" button (`components/NavLinks.tsx:80-88` desktop, `121-130` mobile) shows after login because it's gated on **one condition only** — `hasProfile = Boolean(profile?.onboardingCompletedAt)` — and **never checks auth state**. So any authenticated user without a completed-profile row (Google-signed-in before onboarding, or a profile still keyed to the legacy anonymous UUID) wrongly sees "Login." There's also no way to sign out from the header.

You chose: **gate on auth state**, **sign out in header/profile**, **bug fix + related cleanup**.

## Root cause (verified)
- `NavLinks.tsx:53-55` uses only `useCurrentUser()` (profile-driven). No `useConvexAuth()` anywhere in the nav.
- Server-side `getProfile` (`convex/queries.ts:304`) resolves identity to the Convex auth subject, returning `null` for an authed subject with no profile row → `hasProfile` false → Login button shows despite being logged in.
- Sign out exists only in `LoginCard` (`components/LoginCard.tsx:76-80`), reachable from `/profile` and `/login` — not the header.

## The fix

### 1. Centralize auth state — new `useAuthState()` hook
**File:** `lib/data/provider.tsx` (add near `useCurrentUser`)
A small derived hook so the same bug can't recur elsewhere:
```ts
export function useAuthState(): {
  status: "loading" | "unauthed" | "authed";
  profile: Profile | undefined | null;
  hasProfile: boolean;
} {
  const { isLoading, isAuthenticated } = useConvexAuth();
  const profile = useCurrentUser();
  const hasProfile = Boolean(profile?.onboardingCompletedAt);
  if (isLoading) return { status: "loading", profile, hasProfile };
  return { status: isAuthenticated ? "authed" : "unauthed", profile, hasProfile };
}
```

### 2. Rewrite nav tiers — `components/NavLinks.tsx`
Switch on `useAuthState().status` instead of `hasProfile` alone:

| State | Nav links | Right-side affordance |
|---|---|---|
| `loading` | PUBLIC_NAV (Courses, Learn) | nothing (avoid Login flash) |
| `unauthed` | PUBLIC_NAV (Courses, Learn) | **Login** button → AuthModal |
| `authed` + `!hasProfile` | Courses, Learn, **Profile** | **account menu** (Profile / Sign out) |
| `authed` + `hasProfile` | AUTHED_NAV (Today, Learn, Courses, Build, Progress, Profile) | **account menu** (Profile / Sign out) |

- Desktop: replace the conditional Login button with an **account menu** for authed users — a compact avatar/`UserRound` icon button that opens a small dropdown (`Profile`, `Sign out`). Reuse `useState` + a click-away handler. Keep the existing `AuthModal` for the unauthed Login button.
- Mobile: for `authed + !hasProfile`, add a Profile column + Sign out column (grid adjusts via existing `mobileCols` logic). For `authed + hasProfile`, AUTHED_NAV already includes Profile; add a Sign out entry there too (7 cols is fine on mobile bottom bar, or fold behind a long-press — simplest: append Sign out).
- `signOut` comes from `useAuthActions()` (already used elsewhere in the app).
- Update the docstring (lines 9-18) to reflect auth-driven tiers.

**Tradeoff to note (per your "gate on auth state" choice):** because `AuthBootstrap` signs every visitor in anonymously within ~1s, the Login button is only visible during that brief pre-auth window + for truly unauthed visitors. The upgrade path from anonymous → Google becomes **Profile → "Link Google"** (LoginCard already lives there). I'll make sure `/profile` surfaces that CTA clearly for authed-not-onboarded users.
