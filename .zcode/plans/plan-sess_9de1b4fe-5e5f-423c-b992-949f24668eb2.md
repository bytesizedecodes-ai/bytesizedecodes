### Workstream A — Course lessons become full bytes

The course lesson page (`/courses/[course]/[lesson]`) currently renders only an infographic. We upgrade it to a full Hook-loop byte: **infographic → prose → runnable code cell → MCQ questions → XP reward → review-queue investment**, reusing the existing data-layer machinery that `/bytes/[slug]` already uses.

**A1. Extend `content/courses.ts` `Lesson` type** with optional byte fields:
```ts
type Lesson = {
  slug, title, blurb, topic,           // existing
  prose?: string[],                    // ~150 words of explanation
  exercise?: CodeExercise,             // optional runnable code (reuses content/types CodeExercise)
  questions?: ByteQuestion[],          // optional 2-3 MCQs (reuses content/types ByteQuestion)
}
```
Reuse the **existing** `ByteQuestion` and `CodeExercise` types from `content/types.ts` — no new types invented. Add prose/questions/exercise to the 4 existing ML lessons as real content (not stubs).

**A2. Extract a shared `ByteBody` component** from the existing `app/bytes/[slug]/ByteRunner.tsx` logic — the question-checking UI, code cell, mark-complete, and reward banner. Currently this lives inside `ByteRunner` coupled to the `Byte` type; generalize it to accept `(slug, topic, prose, exercise, questions, today)` so both `/bytes/[slug]` and `/courses/[course]/[lesson]` call the same component. This avoids duplicating ~120 lines of working XP/SRS code.
- `ByteRunner` becomes a thin wrapper passing `byte.*` fields into `ByteBody`.
- The new lesson page passes `lesson.*` fields into `ByteBody`.

**A3. Update `app/courses/[course]/[lesson]/page.tsx`** to render, in order: header → infographic component → `ByteBody` (prose + code + questions + XP) → `CoursePager`. The completion key is `course:${courseSlug}:${lessonSlug}` (distinct namespace from `byte:${slug}` so mastery doesn't collide with `/bytes`).

**A4. itemKey conventions for course lessons:**
- Per-question attempts: `course:${courseSlug}:${lessonSlug}:${questionId}`, `mode: "byte"`, `topic: lesson.topic`.
- Completion: `completeByte(\`course:${courseSlug}:${lessonSlug}\`, today)`.
- These flow through the existing `useSubmitAttempt` / `useCompleteByte` / `useByteProgress` hooks unchanged — the data layer keys on the slug string, so a course-lesson slug works identically to a byte slug. No changes to `lib/data/`.

**A5. The "byte-completed" checkmark** on the course landing page (`/courses/[course]`) and lesson list — wire `useByteProgress(\`course:${courseSlug}:${slug}\`)` to show ✓ on completed lessons (mirrors `app/bytes/ByteStatus.tsx`).

**A6. Brand the lesson page** with a small "byte" affordance — a chip showing "byte · N min · +XP" — so it reads as a Hook-loop Action, not just a reading page.

### Workstream B — The `infographics-custom` skill (project-scoped)

Create `.agents/skills/infographics-custom/` in this repo. Captures the full workflow we just executed manually so future infographic creation is one prompt.

**B1. `SKILL.md`** with frontmatter (`name`, `description` ≤1024 chars, trigger-tuned) and a body documenting the 5-stage workflow:

**B4. `references/workflow-checklist.md`** — the precise file-touch sequence + verification commands, so the agent doesn't miss registry steps.
