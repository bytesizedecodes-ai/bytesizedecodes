## Part 1 — `.agents/agents/` (6 files, format: name/description/tools frontmatter + body = system prompt)

Every prompt bakes in the hard project constraints: **never reformat/dedent course bodies** (33 multi-line template literals — interior whitespace is string content), per-course layout `content/courses/<slug>.ts` (barrel order = listing order), lesson `minutes` untouched (dailyPlan test), exactly 2 scenario MCQs ≥40 chars, jargon parentheticals (beginner/intermediate), color discipline + theme-safe tokens, verify with `tsc` + `vitest` (never `npm run build` — sandbox-broken), never commit.

1. **`course-author.md`** (tools: all) — Level-aware authoring. Reads `level` from the course file → loads the matching v1 skill (`beginner_v1`/`intermediate_v1`/`expert_v1`, v6 for cross-level) → writes lesson data + infographic scene components from the skill's `assets/` templates → registers scenes in `components/infographic/index.tsx` → runs typecheck + `content/*.test.ts` → reports lessons added/files touched/test results. Applies all 7 principles; each lesson must state its chunk plan (≤4 focal elements/scene) and its immediate-win beat.
2. **`course-verifier.md`** (tools: Read, Glob, Grep, Bash — read-only) — The mechanical sweep: `npm run typecheck`, `npm test`, jargon-gate failures with file:line, lesson-vs-`infographic/index.tsx` registration diff, `NEXT_COURSE` slug integrity, registry sync (`catalog.ts`, `tracks.ts`, `skills.ts`, `jargon-terms.ts`, `types.ts` SkillId union), barrel import/array consistency, `minutes` drift check vs git HEAD. Returns a pass/fail table; fixes nothing.
3. **`course-reviewer.md`** (tools: Read, Glob, Grep — read-only) — The craft review against the 7 principles, checking what no test can: visual-first (a table where a picture belongs = Critical), one accent per scene, no literal hex/theme-unsafe tokens, anchor is a 10-year-old-touchable metaphor, diagram formalizes instead of re-telling, MCQs are scenarios not recall, **chunk sizes** (new P), **feedback quality** — MCQ explanations name the misconception, first win arrives early (new P), `whenNot` is a rule not a shrug. Findings tagged Critical / Warning / Suggestion, each with file:line and a one-line fix.
4. **`english-simplifier.md`** (tools: Read, Edit, Bash) — Rule-12 rewrite of ONE course file per dispatch: ~20-word sentences, active voice, everyday words, one idea per sentence, no unexplained idioms, ₹/Indian contexts, simple ≠ shallow (expert precision intact, jargon-exempt). Never touches structure, slugs, ids, `minutes`, question counts. Runs `jargon.test.ts` + `courses.test.ts` on its own output; reports before/after sentence-length stats and changed-line count.
5. **`exercise-test-runner.md`** (tools: Read, Glob, Bash) — Extracts every `CodeExercise` (bytes + courses), verifies `starterCode` runs, writes a reference solution, runs it against hidden `testCode` via local `python3` heredoc (the manual pattern that caught two broken exercises in past sessions — nothing in the suite covers solvability). Reports pass/fail per exercise with the failing assertion.
6. **`infographic-scaffolder.md`** (tools: Read, Write, Edit, Bash) — The mechanical half of a new lesson: scaffolds the scene component from the level-appropriate `assets/` template (shared vocabulary `Scene`/`PictureCard`/`Operator`/`Stagger`/`MotionChild`, theme-safe tokens) and registers it in `components/infographic/index.tsx`. No prose/content writing.
